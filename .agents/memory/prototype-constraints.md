Use one shared family plan with personalized versions for its members. Children need an icon-first home with fewer words; seniors need gentle options; parents need a whole-family view.

Preserve earlier parts, especially the camera core, as new layers are added. Keep prototype data in localStorage. Clearly label simulations as Demo rather than implying real image recognition, a language model, or live communication.

Use Nunito Sans and Lucide icons, with no music, sound, or audio. Avoid emojis outside Family Game Day card/game artwork, where the user explicitly allowed them.

**Why:** These are the user's global rules for the staged, one-day student prototype, repeated in the continuation brief.

**How to apply:** Extend the same family experience, preserve saved progress and previous stages, and keep the distinction between working features and simulations clear.

Parent-and-child camera games use separate, single-person turns, never simultaneous two-person tracking. Children's game progress must come from counted movement or explicitly labeled Demo taps. A jump comparison may use normalized hip rise, never invented centimetres.

**Why:** The user explicitly required these limits for Move's parent/child challenge and jumping games.

**How to apply:** Keep camera ownership tied to the current turn's member, close it at handoff, and preserve these limits when extending family games or reporting measurements.

Eat must not use an external AI API or require an API key. Photo recognition, including a user's own uploaded photo, is a clearly labeled Demo with sample results chosen by photo type.

**Why:** The user explicitly requires this limit for the Eat prototype.

**How to apply:** Keep uploaded photos as local previews, disclose canned detection and cooking tips, and use illustrated placeholders when the supplied sample photos are absent.

Progress must display each family member's points as a family competition. This replaces the earlier no-rankings instruction for Progress.

**Why:** The user explicitly requested a points-based family competition.

**How to apply:** Include every member, preserve earned balances, give equal totals equal ranks, and keep private check-ins out of the competition.

Competition points reward participation, not water volume, sleep duration or a health measurement.

**Why:** Members have different ages and needs, and this remains an educational wellbeing prototype rather than a medical or fitness assessment.

**How to apply:** Reward completed activities without encouraging excess drinking or longer sleep to improve a rank; explain the earning rules visibly.
